# DataTable 契约

状态：行为与默认入口已确认；[Phase 2](frontend-phase-2.md) 已实现直接 props、查询协调、搜索、分页、单列排序、当前页选择及渲染扩展，并验证相应类型。列布局持久化、URL 同步、树与批量业务等后续能力仍按本文补齐。返回 [PRD](../prd.md)。依据：前端 Q22–35、Q164–186、Q213–220、Q224；[历史入口](../decisions/interview-archive-2026-10-15.md#legacy-9-99)。

## 1. 职责与默认入口

DataTable 接收直接 props，内部组合查询与交互 composable；普通页面不必先调用返回绑定组件的 useDataTable，也不使用包揽全部能力的第二套 options 入口。TanStack Table 管理行列交互，shadcn-vue Table 呈现，Vue Query 管服务器资源。

组件持有搜索草稿、已应用搜索、分页、单列排序、当前页选择与列布局。业务提供列、字段、资源 query 工厂、权限与 mutation 回调、资源失效规则。通用组件不引用具体业务 API，不将服务器数据复制到另一状态仓库，不对服务端分页结果再次本地分页／排序。

## 2. Props

| 当前设计入口 | 语义 |
| --- | --- |
| table-id | 稳定列布局身份；不是 queryKey，不混入数据查询身份 |
| query | 资源侧 Query 配置工厂；接收外部 context、已应用搜索、分页与排序，返回查询配置；默认读取已解包 records／total |
| columns | 列定义，稳定列 ID；普通列配置，复杂展示用插槽或渲染函数 |
| search-fields／search-defaults | 可选配置搜索区域与初始值，复用表单能力；草稿与已应用值独立 |
| selectable | 显式开启当前页选择；不得隐含跨页选择 |
| query-context | 可选、类型化、只读外部条件；由页面持有，例如部门 ID |
| query-enabled | 可选，默认 true，表达业务前置条件是否允许查询 |

行键默认 id，允许类型化获取方式覆盖；精确 prop 名、泛型、列扩展和结果读取接口仍需验证。行键必须稳定唯一，缺失／重复是契约错误，不回退到数组下标或随机值。

DataTable 的具体 emits 名单尚未确认；不在文档整理时增加默认受控分页／选择 v-model。特殊受控入口和底层实例扩展需明确所有权，不能绕统一更新路径。

## 3. 搜索、分页、排序与选择

- 点击搜索或 Enter 才应用通过校验的草稿，回第一页并清选择。默认每页 20 条，可选 10／20／50／100，页面可覆盖；修改页大小回第一页并清选择。页大小重开是否保存尚未确认。
- 默认服务端分页与单列服务端排序，仅业务显式声明允许排序的列可参与；翻页、新筛选及查询范围变化清选择。选择仅当前页，不能把 selectedRows 当作另一份服务器资源缓存。
- 同查询成功刷新仅保留仍在当前页且可勾选的 ID；刷新失败不清现有合法选择。新建／编辑保存后保留查询与页码，删除造成越界时返回有效页。
- 目标页无缓存时呈现加载，不拿上一页数据冒充目标结果；有目标查询缓存可先显示，同查询后台刷新保留行。失败弹提示，保持当前查询已有行或空状态，不默认增加错误面板；现有刷新／搜索入口重试。
- 查询、缓存新鲜度、重试、唯一错误提示与取消遵守 [请求与数据契约](http-query.md)，不另建一套规则。

## 4. Slots 与渲染

单元格插槽以稳定列 ID 命名，例如 cell-status；提供有类型的原始行及单元格上下文。优先级为：存在对应插槽 → 列渲染函数 → 默认展示。插槽返回空内容仍算已选择插槽，不回退或执行两遍。

工具栏插槽提供只读状态和明确命令，业务在此放新增／批量等操作。工具栏及其他槽的精确名称、上下文类型继续验证。渲染函数必须支持，模板外组件值按 [工程架构](architecture.md) 显式导入。

普通纯文本默认单行省略，鼠标和键盘可查看完整内容，允许列级覆盖为换行。自定义业务渲染由页面负责，同时遵守权限和操作状态。

## 5. 列布局

列显隐、拖拽顺序和列宽调整作为首版可开启能力。按应用、稳定 tableId 和 columnId 本地保存布局，默认不按账号隔离；不把行数据、勾选和权限存入布局。

固定列归属由开发者配置，用户不能修改固定分区；顺序在合法分区内处理，必要列不可隐藏。升级保留合法覆盖，清除已删除列配置；新增普通列按定义顺序追加到中间区域末尾。没有用户覆盖时采用现版本开发默认。

单表 resetLayout 清除该表本地保存的布局覆盖，再按当前开发默认恢复显隐、顺序和宽度；不把默认值重新存成用户覆盖，不修改搜索、排序、分页、选择或其他表格；全局显示偏好恢复是另一职责。存储版本／迁移、跨窗口冲突、拖拽边界与宽度上下限待实现方案验证。

## 6. Methods 与只读状态

| 方法 | 语义 |
| --- | --- |
| refresh() | 重取当前已应用条件和当前页，不提交草稿 |
| submitSearch() | 校验草稿，通过后应用、回第一页并清选择 |
| resetSearch() | 草稿及已应用搜索回配置初值，回第一页并清选择；保留排序、布局和外部 context |
| clearSelection(ids?) | 不传时全清；传 ID 快照时仅移除这些目标 |
| resetLayout() | 仅重置本表列布局 |

公开只读 selectedIds／selectedRows／isLoading／isFetching／error。isLoading 表达当前查询没有可展示结果且在请求，isFetching 表达在途；刷新已有结果不伪装首次加载。error 是当前查询错误，不制造另一份错误状态或重复提示。

默认工具栏、插槽和组件 ref 复用同一行为路径。请求命令可等待，并区分成功、失败、校验未通过、未执行和被取代；具体联合类型待定。未挂载、生命周期失效或条件不允许时不得伪装执行成功。

## 7. 外部条件与启用状态

query-context 的有效内容变化统一回第一页、清选择并切换查询，保留已应用搜索、草稿、排序、布局；内容相等的新对象不触发重置。资源工厂分别接收 context 与表格条件，不用任意展开覆盖保留字段；一次协调完成后查询，避免中间状态重复请求。

外部部门树由页面组合，不纳入 DataTable，不自动增加树形行。普通列表无需传外部 context。

query-enabled=false 时保留搜索区域及可编辑草稿，结果区显示可定制等待提示，例如“请先选择部门”；不显示为 loading 或成功空结果，不呈现其他上下文旧行和批量目标，清选择。请求命令不能绕过，resetSearch 可本地恢复但不请求，clearSelection／resetLayout 等本地命令仍可用。

重新启用按当前已应用条件查询，不自动提交草稿或仅因开关变动重置页码；context 同时有效变化仍遵守其重置规则。禁用不删除共享缓存、不承诺取消已发读取，迟到读取不得恢复过期上下文界面。有效启用条件共同包括账号就绪、页面可见、资源条件和 query-enabled。

## 8. 可选 URL 同步与缓存页面归属

默认不修改 URL。页面显式声明允许同步的字段及类型，只同步已应用搜索、分页、排序和明确允许的外部条件；排除未提交草稿、勾选、行数据与敏感字段。用于刷新恢复、收藏／分享查询，不承诺服务器结果永远不变。

公共适配层负责路由读写，DataTable 核心不依赖 Router。地址变化与组件操作经同一入口协调，不维护两套互相监听的可写镜像。初次校验／应用地址后才允许查询；非法／不支持参数按声明回退或忽略，不直接送 API。

默认 replace 当前历史条目，搜索、翻页、排序不追加；明确需要回溯步骤的页面可选另一策略。无语义变化不导航，参数修正不增加历史条目。

外部导航确实改变有效查询状态时，恢复已应用条件及参与同步的搜索字段草稿；未声明字段保留，缺失字段取声明默认。合法目标页不能被外部 context 的中间联动误重置成第一页。自身回写、普通翻页及无关参数变化不覆盖草稿；单纯外部 context 变化沿用保留草稿规则。业务编辑未保存保护不受影响。

Q224 A：适配绑定既定路由／标签身份，仅当前匹配的活动实例读写当前地址。失活页面保留自身条件与草稿，不应用其他页面同名参数、不回写其他页面地址。重新激活先协调本标签的有效目标地址再启用查询；有效状态未变保留草稿，有新查询按前述恢复。排队或迟到回写执行前再次验证当前目标。query 不因此自动加入标签身份。

精确 URL codec、状态协议、导航失败及排队回写机制待验证；[标签身份与缓存](application-shell.md) 由应用层维护。

## 9. 业务操作边界

可选轻量按钮组只统一操作 UI，业务回调负责 API／mutation；无权限默认隐藏，业务暂不允许可禁用并说明原因。前端隐藏不是后端授权。

批量点击时复制目标 ID，确认文案和请求使用同一快照，不读取后来变化的实时勾选。业务契约确认整批完整成功后仅取消本次目标 ID，保留其他仍合法选择；HTTP 200 不自动代表全部完成，部分结果须有明确业务处理。清选只作用于仍属于本次账号和列表实例的状态。单行和批量删除使用统一模态确认，展示目标或数量，确认后才写入。

pending 时确认弹窗等待结果，防重复／取消／Esc；明确成功关闭，明确失败保留并恢复操作。行内写只锁本目标重复／冲突写，不整表锁定无关记录与只读操作，但仍遵守模态层自身的交互限制。适合单个数据库事务的常规小批量默认全成功或全不执行，由后端保证；连续发送多个单条请求不等于整批事务，外部系统／长任务须单独论证。

超时／断网不能判为未执行；恢复关闭能力并显示未知，后续遵守 [未知写入保护](http-query.md#write-unknown)。不因关闭重开恢复冲突写，不自动重试／离线排队。

## 10. 待验证与验收

待定义列类型与项目扩展、行 ID、query 参数／context／结果泛型、events／slot 参数、命令返回联合、底层扩展、URL 适配和列布局持久化协议。树形表格、导出、虚拟滚动不因底层支持就纳入首版。

验收覆盖服务端分页／排序、草稿与应用值隔离、0／false 查询值、缓存与加载、同查询选择交集、目标快照、列升级与重置、插槽存在但为空的优先级、前置条件开关、外部 context 原子切换、两个缓存页面同名 URL 参数互不影响、同路由不同路径参数实例、切回草稿保留、新链接恢复、迟到回写、写入未知与权限变化。
