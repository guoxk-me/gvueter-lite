# 请求、Query 与 API 契约

状态：产品行为已确认；[Phase 2](frontend-phase-2.md) 已实现并验证 Axios JSON 边界、Query 默认策略、统一读取错误、资源写入保护与同标签恢复。正式认证、OpenAPI、特殊响应与真实业务核实仍待接入。返回 [PRD](../prd.md)。依据：前端 Q93–112、Q178–186，整体复查 Q57–Q58；[历史原文](../decisions/interview-archive-2026-10-15.md#legacy-9-26)。

## 1. HTTP 与接口来源

使用 Axios，集中基础地址、凭据、超时、成功解包与传输错误处理，不另造通用资源框架。默认同源 /api，本地 Vite 代理；认证、跳转与账号清理由上层 auth／router 协调，http 不反向引用 pages／router。

成功 JSON 用 data 包裹并默认解包，分页内容使用 records／total。下载、无正文或其他特殊响应显式选择对应处理，不能一律当 JSON data。错误使用稳定 code、可展示 message、可选字段错误和 requestId；完整字段路径与错误码表仍待定义。失败使用正确 HTTP 状态，不统一返回 200；需要响应头等信息时提供显式原始响应入口。

后端根据请求语言生成可展示的业务 message，前端优先展示，不为每条业务 code 重复维护文案；无服务端文案的网络／通用错误由前端国际化兜底。稳定 code 用于程序判断，不能按 message 文本分支。服务端输出不暴露内部秘密或诊断堆栈给普通用户。

OpenAPI 显式同步，规范快照与生成 TypeScript 类型提交到仓库；业务 API 函数手写，类型不手改。日常类型检查／构建不依赖后端在线或临时下载规范；可选 Mock 按相同契约维护，不能把 Mock 通过当作真实联调通过。

## 2. 错误提示与超时

默认 HTTP 超时 30 秒，可按接口覆盖。取消、网络失败、超时、HTTP 错误、字段错误、认证失败分别识别；取消默认静默。请求失败抛统一错误，不吞成成功空数组。

应用层有唯一提示责任，字段错误就地展示，其他错误统一兜底；多个 observer 不重复弹同一失败。精确去重范围及接口待定。表格错误保持空或同一查询已有结果，不展示其他查询结果，不增加默认错误面板。

明确会话失效才清账号状态并转登录，保留安全站内返回地址并在登录后重新鉴权；暂时网络／5xx 不误判失效，无权操作不一律退出。旧操作不自动重放，身份上下文错配按 [身份契约](identity.md) 单独处理，不能清除另一个有效新会话。

## 3. Query 缓存与重试

| 规则 | 默认 |
| --- | --- |
| 新鲜期 | 30 秒，业务可按场景覆盖 |
| 无订阅缓存回收 | 5 分钟，从最后 observer 移除后按库生命周期处理 |
| 自动刷新 | 页面可见且 stale 时，焦点／重连可刷新 |
| 隐藏缓存页 | 默认暂停自身后续自动查询，业务可显式声明后台需要；已发只读请求允许完成 |
| 只读自动重试 | 网络失败、适合重试的 5xx、超时最多一次，由 Query 层负责 |
| 不重试 | 401／403、校验／其他业务错误、主动取消；Axios 不叠加重试 |
| 写入 | 不自动重试，离线不排队；恢复网络或认证后不自动重放 |

查询键按资源就近统一管理，覆盖影响结果的全部条件及账号隔离；页面读取、mutation 后更新／失效使用相同资源约定。query 目录仅存全局运行规则，不再放另一份业务 key 清单。服务器资源不复制到 Pinia。

隐藏不等于卸载，disabled 不等于移除 observer；其他可见使用者仍可更新同 key。请求取消需要请求函数消费 signal，不能用取消替代正确查询身份及迟到回调隔离，也不能承诺服务器写入回滚。账号退出／切号需失效旧任务并清理账号缓存，区别于普通页面隐藏。

编辑只从满足完整性、新鲜度和身份条件的详情缓存建立一次快照；持续 Query 更新不直接覆盖编辑输入。保存后的相关查询更新／失效由业务声明，写入成功与后续读取失败分开报告。

## 4. 写入结果未知与冲突保护

超时、断网或响应丢失不证明写入未发生。明确失败、明确成功和结果未知必须分别表达；不能因客户端取消或清状态宣称服务端回滚。

存在适用查询且当前允许读取时，主动执行一次相关数据的只读核实，不自动重发写入、不新增持续轮询。业务提供可靠核实依据；旧数据或当前页没有某记录不足以证明成功／失败，无法确认继续显示未知。

整体复查 Q57 A：未知状态独立于弹窗实例保存；允许关闭，但关闭／重开不解除相关重复／冲突写保护。相关缓存标记失效，即便有新鲜缓存也不能绕过保护。业务提供账号内资源／操作身份、冲突范围及可靠核实／安全重试依据，公共层不得只根据按钮标题猜测。无关记录和非冲突操作不受影响。

迟到结果可按账号／操作身份更新仍有效的操作状态，记录结果与弹窗是否挂载分别处理；不得更新已失效组件或新账号界面。不能因每次重开再触发自动核实而形成变相轮询；无适用查询、离线或无权限时保留适用的手动核实入口或对应提示，不能提供无依据的强制重试。

整体复查 Q58 A：sessionStorage 保存最小操作标记，同一浏览器标签内刷新后先核对可信账号，再恢复匹配账号的提示与冲突限制；身份未确认时不显示旧操作信息。首版不提供跨窗口同步，不承诺跨设备或浏览器标签关闭后的恢复。

发送相关写请求前登记最小未决标记，覆盖请求在途时刷新；明确结果后更新／清除，刷新后的未决标记按待确认处理，不认定失败或自动重放。标记仅保存账号范围、资源／操作标识和必要状态元信息，不保存凭据、完整请求内容或表单草稿；字段白名单、版本与存储内容须校验，不据客户端标记直接执行写操作。

退出／切换账号清理对应业务操作标记和内存状态，重新登录不承诺恢复已清理标记。Q223 的退出待确认是独立控制状态，不能被这项业务标记清理一并抹掉，导致刷新后静默恢复旧账号。存储不可用／写失败明确反馈刷新恢复不可用，当前运行内存保护继续生效；不谎报持久化，也不把存储失败说成服务器写入失败。重新读取或标记存在时长不证明业务结果，解除仍需可靠核实或安全重试依据；服务端负责最终授权、幂等及并发安全，客户端标记不替代这些能力。

## 5. 待验证与验收

待定义 API 路径、DTO 与响应类型、稳定错误码、字段错误映射、语言协商、OpenAPI 生成／同步脚本、Query 工厂泛型、错误去重、失效时机、未知操作身份与核实协议。后端 Users／Roles／认证业务接口在迁移时尚未实现。

验收覆盖解包与特殊响应、错误唯一提示、字段错误和未知字段兜底、取消静默、重试次数与超时、离线不排队、同查询缓存保留及不同查询隔离、隐藏 observer 与共享 observer、写成功刷新失败、未知状态跨弹窗及同标签刷新恢复、在途刷新后待确认、身份核对与退出清理、存储失败降级、真实后端契约与离线构建。
