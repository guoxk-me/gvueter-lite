# 身份、会话与权限契约

状态：已确认设计，认证与授权业务尚未实施。本文整理既有选择，不构成新增认证 API／模型的实施授权。返回 [PRD](../prd.md)。依据：前端 Q46、Q64–92、Q102、Q136、Q221–223，后端 Q19–24、Q54；[历史认证讨论](../decisions/interview-archive-2026-10-15.md#legacy-9-11)。

## 1. 登录和会话边界

用户名＋密码登录，无公开注册，账号由超级管理员创建。默认同源 /api；浏览器以 HttpOnly Cookie 携带会话凭据，服务端会话为权威。PostgreSQL 保存权威会话，使用已选 TypeORM；不采用生产内存会话存储。认证库尚未选定，历史第三方库比较不等于采用该库。

| 模式 | 空闲期限 | 绝对期限 | 选择 |
| --- | --- | --- | --- |
| 普通登录 | 8 小时 | 24 小时 | 默认 |
| 记住我 | 7 天 | 30 天 | 登录提供，默认不勾选 |

期限均可配置，活动续期不能突破本次登录的绝对期限。Cookie 持久性与服务器期限分别检查，Cookie 存在不证明会话有效，关闭浏览器不保证即时退出。业务请求计入活动；心跳、纯会话检测、后台自动刷新不计入，纯本地输入不必然延长会话。

允许多设备独立会话；同 Cookie 范围的浏览器标签共享登录，普通退出只终止当前会话，不承诺只影响一个窗口。每次请求校验会话、当前账号状态及授权，存储故障不得跳过认证。

首版提供完整后端会话管理 API：列出会话、撤销当前／指定／其他／全部会话、期限与续期、账号停用失效、多实例和重启恢复；禁止越权查询或撤销他人会话。设备管理 UI 非首版必备。不额外增加统一“近期密码复核”窗口，本人改密仍验证旧密码。

活动写入节流、过期清理、撤销与登录竞争须明确定义；撤销后的续期不得恢复旧会话。账号／密码变化与会话状态以一致事务协调，数据库提交与 HTTP Cookie 写入不是同一事务。

## 2. 账号与密码生命周期

| 操作 | 已确认规则 |
| --- | --- |
| 初始管理员 | 部署者显式执行一次性初始化命令；无固定默认密码，重复／并发执行不绕过约束 |
| 创建账号／管理员重置 | 安全随机临时密码，成功时仅展示一次，不提供后续明文查询，不持久化明文 |
| 临时密码期限 | 生成后 24 小时，可配置；重新生成令旧密码失效 |
| 临时密码登录 | 只能进入必要改密流程；过期不删除账号，改成正式密码后不再受旧临时期限影响 |
| 本人改密 | 验证旧密码；临时登录时旧密码就是临时密码。撤销其他会话，轮换当前凭据并保留当前登录，旧凭据失效 |
| 管理员重置 | 撤销目标账号全部旧会话，不因此登录成目标用户 |
| 忘记密码 | 超级管理员重置，无公开自助找回 |
| 超级管理员恢复 | 部署者独立命令为已有超级管理员生成临时密码并撤销旧会话；不能任意提升普通账号 |

保存必要的带盐哈希、临时期限和强制改密状态；不向普通日志输出凭据。临时密码可信交付、受限会话期限／允许入口、是否禁止新旧密码相同、初始化／恢复命令精确协议仍待定义。

正式密码采用 Q89 B：8–64 字符，必须含字母与数字，符号可选；拦截本地常见弱密码，允许粘贴和密码管理器，不定期强制更换，也不强制大小写、数字、符号全部具备。统一字符计数与 Unicode 处理，禁止静默截断。这是项目选择，不宣称满足历史引用 NIST 的全部建议。

## 3. 角色与授权

单组织，每用户一个角色。角色维护界面支持创建自定义角色并勾选开发者预定义的 action＋subject 权限；不能任意创建操作／资源名或编写 CASL 条件。首版仅资源类型级权限，未配置默认拒绝，删除独立于编辑授权；条件／字段权限按具体场景扩展。

前端 CASL 控制菜单、路由和按钮；后端基于可信身份独立检查当前权限，不能信任前端传来的规则。权限变更后后端下次请求按当前状态执行；前端在登录、刷新、权限被拒绝等约定节点同步，不默认增加实时推送。

内置超级管理员角色拥有全部操作权限并受保护，不可删除或由普通角色编辑缩减权限；禁止超级管理员停用、删除或降级自己，始终至少保留一个启用超级管理员。已有关联用户的角色不可删除，先调整角色分配。全部写入口必须共同保证不变量，不能只隐藏按钮或无锁计数。

后端 Q54：用户／角色管理列表、详情和全部管理写操作均为超级管理员专属。普通角色的可选目录不含这些权限，伪造提交也不能授予。本人的资料／改密使用独立契约，只允许本人及明确可编辑字段；业务需人员选择时按业务权限返回必要 ID／名称，不能借此开放账号管理详情、凭据或会话资料。

权限同步后移除不可访问标签、释放实例、停止旧操作，隔离迟到响应并清理不可再用缓存；合法共享缓存保留。当前页面失权显示无权访问，普通操作 403 不一律登出或销毁整页。同步失败不能当作已确认无权限。

跨模块写通过同一事务 manager；角色分配／删除、最后管理员、改密／撤销／登录竞争需共同锁点、锁后重查、约束与统一锁顺序。精确模型和锁协议待业务方案验证。

## 4. 跨窗口身份变化（Q221）

发现其他窗口切换登录身份后，先停止旧操作、失效旧任务，清理旧账号页面、权限、草稿、选择与业务缓存，提示“登录状态已变化，请重新进入”。用户点击后核实当前会话再初始化；有效会话不一律要求再次输入密码，失效则走登录。

不自动重放旧操作，不保留旧账号草稿供新账号使用。账号变化不同于普通关闭确认，不能因草稿未保存而继续以新身份操作旧页面。不增加每个标签独立登录模型。

## 5. 请求登录上下文绑定（Q222）

1. 登录／身份恢复成功返回与逻辑登录会话绑定的非凭据标记，暂称 authContext。重新登录建立新上下文，同次逻辑登录的正常凭据轮换保持其语义；标记不能单独认证、不含凭据或口令。
2. 受保护业务请求携带本窗口已核实的标记。服务端先校验 Cookie 会话及账号状态，再比对上下文；缺失／错配在业务执行前拒绝并返回可区分稳定错误。不能按客户端标记选择账号或信任权限。
3. 错配不得撤销／清除另一个已有效的新会话，不自动获取新标记重放旧请求。登录及明确身份引导接口为专门例外，仍执行自己的认证、防滥用和 CSRF 规则。
4. 跨窗口通知仅用于及时失效旧界面，不作身份真相，不携带凭据／业务数据。窗口恢复、通知缺失／延迟和核实失败有明确降级；未经主动重新进入不静默恢复旧操作。业务前单独查一次身份存在请求间切号窗口，不能替代同请求校验。
5. 本地身份代次结合组件／请求生命周期隔离迟到查询、mutation 回调与初始化；先失效旧代次再清理，错配结果不写入旧账号缓存。旧身份下已合法开始的服务器写入不因前端取消／切号承诺回滚。
6. 退出也绑定调用窗口已核实上下文及服务端本次解析会话，滞后退出不得撤销新登录。旧退出／轮换响应晚到时，浏览器仍可能应用 Set-Cookie；丢弃 JS 回调不能阻止它。认证原型必须验证 Cookie 写入乱序，不得恢复已撤销会话或混用身份，必要时明确重新确认／登录。

这是项目防意外身份错配协议，不是浏览器或 OWASP 已定义的现成标准；不替代 HttpOnly／Secure／SameSite、CSRF、防 XSS、最终授权和服务端撤销。头名、标记生成／存储、错误码／HTTP 状态、引导例外、通知和 Cookie 协调尚待精确协议及真实浏览器验证。

## 6. 主动退出失败或结果未知（Q223）

用户主动退出并完成适用的未保存确认后，先停止本窗口业务操作、隔离旧任务、清理账号状态并离开后台界面，保留显示偏好。呈现退出处理状态；只有服务端明确确认才显示“退出成功”。

失败或未知显示“已离开当前账号页面，服务端退出尚未确认”，允许主动重试，不静默恢复原账号。刷新后的身份恢复不能绕过待确认状态；其持久化范围、存储不可用降级和主动重新登录衔接仍需精确契约，本地清理不代替服务器撤销。

重试沿用原登录上下文，不能动态改用新账号上下文去退出。身份错配不能显示原会话已撤销；网络恢复不自动重放退出。旧响应的 Cookie 乱序继续按 Q222 验证。普通业务网络错误不等同用户主动退出。

## 7. 实施前门槛与验收

须确定认证依赖、哈希及防滥用、Cookie 属性／CSRF／代理信任、会话数据模型、清理／活动分类、认证与管理 API、并发锁协议、上下文协议和退出待确认恢复策略，再形成可审查实施范围。

验收至少覆盖两种登录期限、活动／后台请求区别、多设备撤销、重启与存储故障、临时密码到期及轮换、最后管理员和角色删除并发、普通角色直接越权、本人操作字段约束、两窗口甲→乙切号、通知丢失、旧窗口读／保存／退出拒绝、迟到回调、旧 Cookie 响应乱序、正常轮换不误报、退出失败／刷新／重试不影响新账号。当前均为验收要求，未运行。
