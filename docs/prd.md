## 2. 产品定位与范围

Gvueter Lite 面向个人与 AI 协作开发、熟悉 Vue 的小团队，交付可复制源码后二次开发的生产级轻量管理后台模板。各项目可以独立演进；前端为主，参考后端可替换，前后端使用两个独立仓库。

全部重新规划，不以旧版实现为基线。免费开源 Admin 模板的源码研究用于理解取舍，不自动成为产品要求。核心目标是现代化、新、简洁、方便、清晰；Lite 限定功能和架构规模，已选核心能力仍须完整交付。

| 首版必须具备 | 范围边界 |
| --- | --- |
| 登录、账号会话、权限和管理基础 | 单组织、每部署一个组织；细则见身份契约 |
| 布局与导航 | 单一侧栏、面包屑、菜单搜索、多标签；桌面使用 |
| 主题与国际化 | 简体中文和英语；显示偏好本地保存 |
| 数据访问与反馈 | HTTP、服务器状态、统一错误、明确失败与未知结果 |
| 公共能力 | 配置表单、FormDialog／FormDrawer、DataTable、确认交互 |
| 代表性业务流程 | 列表、查询、新增、编辑、删除验证公共封装；最终完成真实后端联调 |
| 工程交付 | 类型、依赖边界、检查、构建、少量开发示例与接入说明 |

上传、富文本、图表、导入导出、复杂表单等按明确场景扩展。多租户、复杂插件平台、可视化页面设计、树形表格及手机适配不自动纳入首版。外部部门树可由页面与 DataTable 组合，不等于增加内置部门业务模块。

## 3. 技术与封装原则

| 职责 | 已选方向 |
| --- | --- |
| 前端 | Vue 3、Vite、Vite Plus、严格 TypeScript |
| UI | shadcn-vue 源码与自有封装分开维护 |
| 表单 | TanStack Form＋Zod；公共层负责条件字段、适配、联动和生命周期 |
| 表格 | TanStack Table＋shadcn-vue Table；DataTable 作为默认业务入口 |
| 服务器资源 | TanStack Vue Query；业务查询键归资源侧 |
| 状态 | Pinia 仅存确需跨页的客户端状态，局部状态归组件／composable |
| 请求 | Axios 与统一响应／错误契约 |
| 权限 | CASL；资源类型级 action＋subject，后端执行最终授权 |
| 参考后端 | NestJS 12＋TypeScript＋原生 ESM＋Express；官方 typescript-starter |
| 数据访问 | PostgreSQL＋TypeORM；数据库保存权威会话；后端 pnpm |

前端检查工具职责已按 Q227 最新决定修订为不使用 ESLint 工具链，详见 [工程架构契约](contracts/architecture.md)；具体依赖版本、样式配置、自动导入名单与检查命令仍须在工程方案中验证。后端已交付的锁定版本与测试记录保存在历史归档，本轮不重新宣称其为最新版本。

基础组件按实际需要直接使用，不强制逐个转发包装。公共封装负责稳定接口、默认策略、跨库状态协调、错误和生命周期；不能以“库已有 API”代替模板交付。保留明确扩展点，业务页面主要提供字段、列、资源查询／保存函数和业务规则，不复制共同机制。

前端初始化须先更新 Vite Plus，再通过 `vp create` 创建 Vue 3＋TypeScript 模板；以官方生成工程为起点，具体顺序见 [Phase 1 方案](contracts/frontend-foundation.md)。此初始化方式已确认，Q228 已确认 A，Phase 1 本地验收已完成。

## 4. 架构职责

前端顶层按职责组织，页面私有组件和逻辑就近；公共表单／表格不引用具体业务 API。服务器缓存不复制到 Pinia；共享纯类型有明确归属，运行时逻辑留在所属实现。

DataTable 通过直接 props 接收配置，内部组合查询与交互；表单默认组件内部持有字段状态，编辑容器由页面持有 open／context。这些默认入口不改为页面先创建控制对象的另一套强制 API。

后端使用模块化单体。identity 协调 users、sessions、access 的公开能力；模块拥有自己的实体、仓库和规则。业务身份与事务 manager 显式传递。具体目录、公开文件、依赖例外和新增能力流程以 [工程架构契约](contracts/architecture.md) 为准，目录示意不表示业务模块已存在。

## 5. 业务与安全责任

模板交付完整的登录恢复、权限加载、路由就绪、账号隔离和退出流程；前端菜单／按钮限制不能代替服务端授权。用户及角色管理全部为超级管理员专属；本人操作使用独立契约。

表单维护编辑快照和条件字段规则；DataTable 维护草稿／已应用搜索与表格交互；业务负责具体字段权限、保存、资源更新及写入未知结果的核实依据。组件内部请求失败、写入成功后的刷新失败与服务器写入结果未知必须区分。

跨窗口身份变化、旧任务隔离、退出待确认及缓存页 URL 归属属于已确认需求，实施时必须覆盖真实竞态。当前会话期限、密码规则和 authContext 设计见 [身份契约](contracts/identity.md)，不能用浏览器广播或前端清缓存代替服务端控制。

## 6. 配置责任

| 配置类别 | 产品定位 |
| --- | --- |
| 开发者配置 | 品牌、路由、模块、默认布局等源码配置，首版必备 |
| 部署配置 | API 地址、部署路径等构建时输入，首版必备，关键无效配置明确阻止进入业务 |
| 个人显示偏好 | 浏览器本地共享；字段覆盖、同步、失败和升级规则见应用外壳契约 |
| 管理员业务设置 | 首版提供接入说明，明确需求后在所属业务实现页面 |
| 动态页面配置 | 按明确场景决定，不作为默认表单配置能力 |

前端公开配置不得包含秘密。后端 YAML／env 由专用加载边界校验，不能将前端构建配置与后端进程运行配置混为一谈。

## 7. 验收原则与交付阶段

[Q226 A](decisions/226-frontend-delivery-order.md) 已确认：基础工程 → 固定 Mock 的最小完整流程 → 补齐首版能力 → 真实接口联调。最小流程验证搜索、分页、新增／编辑、保存刷新和失败处理，以及 FormDialog／DataTable／Vue Query 协作；不会删减九类控件等既定首版范围。开始编码前先形成具体工程方案。

行为验收以完整业务流程为单位。类型检查验证契约可用性；关键负向样例验证不能配置错误字段、值类型或依赖方向；局部测试验证真实边界，浏览器流程验证交互、生命周期和竞态。

| 阶段 | 必须产出的证据 | 当前状态 |
| --- | --- | --- |
| 需求与契约 | 当前规则、可追溯决策、显式待定项 | Q225 已确认，文档已分流；精确契约仍有待验证项 |
| 前端基础工程 | 工具版本、类型／Lint／格式职责、边界检查、构建与最小启动 | [Phase 1 记录](contracts/frontend-foundation.md)：Q228 A 已完成本地验收，7 项测试与 2 项浏览器流程通过 |
| 核心能力原型 | 类型样例、FormDialog／DataTable 的最小完整流程与关键失败分支；随后补齐 FormDrawer 等首版能力 | [Phase 2 记录](contracts/frontend-phase-2.md)：2026-10-16 已完成联系人 Mock 本地验收，39 项测试与 12 项浏览器测试通过；其余首版能力继续补齐 |
| 真实纵向流程 | 登录、身份恢复、权限、真实业务 API、表单与列表协作 | 尚未就绪；Users／Roles／认证业务接口尚未实现 |

后端历史记录包含基础工程 Q12、架构 Q35、日志 Q53 的交付与测试证据；整体复查 Q56 的关闭期限补充在迁移时仍标为待实施。此处只迁移记录，未重新运行后端测试或核实部署。新增实施结果必须标明实际执行时间和范围，不能覆盖历史证据。

本轮整体复查的后端 Q54 管理权限边界、Q55 非法输入保护、Q57–Q58 未知操作恢复已落实到对应契约。Phase 2 已验证前端最小流程和 Mock 未知恢复，真实业务及认证接入仍待开展；Q56 关闭故障修复与测试仍按后端记录追踪。Q59 的文档整理由现有三类结构承接，具体追踪见 [复查记录](decisions/review-059-document-consolidation.md)。

验证报告区分 Executed（实际执行）、Inspected（阅读核对）、Assumed（尚未验证的判断）；Mock 演示、真实服务联调、提交／合并与部署验收分别报告。
